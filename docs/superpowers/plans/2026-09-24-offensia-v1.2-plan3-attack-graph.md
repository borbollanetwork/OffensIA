# OffensIA v1.2 — Plan 3: Attack Graph Integration

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the standalone attack-graph store into a live, finding-fed graph: validated findings emit nodes/edges automatically, `paths()` returns confirmed paths using only validated edges (candidate paths separated), paths are ranked, crown jewels are explicit, and a remediation ranking names the fix that breaks the most confirmed paths — all exposed through `offensia_graph_paths`.

**Architecture:** The finding lifecycle is the single writer into the graph: when `offensia_validate_finding` promotes a finding to a validation-gated state, an emitter turns that finding's `requires`/`grants` into graph nodes and edges whose `validation` reflects the finding's state. Reads split hard: `confirmed_paths` traverse only `validation="validated"` edges; `candidate_paths` include unvalidated edges and are returned separately and labeled. Ranking and remediation are pure functions over the stored graph. The MCP tool never lets the model hand-author edges; it only reads.

**Tech Stack:** Python 3.11+, stdlib only (`sqlite3`, `json`), `mcp` (pinned `>=1.2,<2`), pytest/ruff/mypy.

**Spec:** `docs/specs/2026-09-23-offensia-v1.2-autonomous-core.md` §2.5 + accepted `melhoria.md` §9.

## Global Constraints

- Python 3.11+; stdlib only; no new dependency; `mcp` pin unchanged.
- **Validated-only confirmed paths:** `confirmed_paths` MUST traverse only edges with `validation == "validated"`; an unvalidated edge never appears in a confirmed path. Candidate paths (which may include unvalidated edges) are a separate, clearly-labeled result — never merged into confirmed.
- **Graph is finding-fed, not model-authored:** nodes/edges are emitted from the finding lifecycle (on validation-gated promotion). The MCP surface is read-only for paths; the model cannot inject arbitrary edges through a tool.
- **Evidence-first:** an emitted edge carries the finding's `evidence_refs`, `confidence`, and `validation` (validated only when the finding reached a validation-gated state).
- Adapters/tools never raise into the MCP layer; graph errors return structured results.
- Backward compatible: the existing `attack_graph.sqlite` schema and `add_node`/`add_edge`/`neighbors` keep working; existing assessments load.
- Each task is TDD, runs with no live target, and leaves `ruff check .`, `mypy offensia`, `pytest -q` green before its commit. Baseline: branch from current `main` HEAD (169 passing, `c289212`).

## Review Focus

- **Confirmed path leaks an unvalidated edge** — a graph with one validated and one unvalidated edge on a route must yield that route only under candidate_paths, never confirmed_paths. (Task 1)
- **Emitter double-writes / duplicates nodes** — validating the same finding twice must not create duplicate finding nodes or duplicate edges (idempotent by finding_id). (Task 2)
- **Emitter never breaks validation** — an emitter failure (bad requires/grants shape) must not fail `offensia_validate_finding`'s promotion (best-effort, structured). (Task 2)
- **Ranking is deterministic** — same graph → same ranked order (stable tie-break). (Task 3)
- **Remediation on an empty/cyclic graph** — `fix_ranking` on no confirmed paths returns `[]`; a cycle does not hang (bounded traversal). (Task 4)

```python
def paths(assessment_dir, src, dst, max_depth=8, *, validated_only=False):
    with _db(assessment_dir) as conn:
        rows = conn.execute("SELECT src, dst, validation FROM edges").fetchall()
    adj: dict[str, list[str]] = {}
    for s, d, val in rows:
        if validated_only and val != "validated":
            continue
        adj.setdefault(s, []).append(d)
    out: list[list[str]] = []

    def dfs(node, path):
        if len(path) > max_depth:
            return
        if node == dst:
            out.append(list(path)); return
        for nxt in adj.get(node, []):
            if nxt not in path:
                dfs(nxt, path + [nxt])
    dfs(src, [src])
    return out


def confirmed_paths(assessment_dir, src, dst, max_depth=8):
    return paths(assessment_dir, src, dst, max_depth, validated_only=True)


def candidate_paths(assessment_dir, src, dst, max_depth=8):
    conf = {tuple(p) for p in confirmed_paths(assessment_dir, src, dst, max_depth)}
    allp = paths(assessment_dir, src, dst, max_depth, validated_only=False)
    return [p for p in allp if tuple(p) not in conf]
```

```python
"""Finding -> attack-graph emitter. The finding lifecycle is the graph's single
writer: a promoted finding turns its requires/grants into nodes and edges whose
validation reflects the finding's state. Idempotent by finding_id; never raises."""
from __future__ import annotations

from pathlib import Path

from offensia.core import attack_graph as ag
from offensia.core import finding as fnd


def _find_node(adir: Path, kind: str, label: str) -> str | None:
    import sqlite3
    try:
        with sqlite3.connect(Path(adir) / "attack_graph.sqlite") as c:
            row = c.execute("SELECT id FROM nodes WHERE kind=? AND label=?",
                            (kind, label)).fetchone()
        return row[0] if row else None
    except sqlite3.Error:
        return None


def _ensure_node(adir: Path, kind: str, label: str, meta: dict | None = None) -> str:
    existing = _find_node(adir, kind, label)
    return existing or ag.add_node(adir, kind, label, meta)


def _has_edge(adir: Path, src: str, dst: str, kind: str) -> bool:
    return any(e["src"] == src and e["dst"] == dst and e["kind"] == kind
               for e in ag.edges(adir))


def emit_from_finding(assessment_dir, finding) -> dict:
    adir = Path(assessment_dir)
    validated = finding.status in fnd.VALIDATION_GATED
    val = "validated" if validated else "unvalidated"
    nodes_before = _count_nodes(adir)
    edges_before = len(ag.edges(adir))
    fnode = _ensure_node(adir, "finding", finding.finding_id,
                         {"title": finding.title, "status": finding.status})
    for req in list(getattr(finding, "requires", []) or []):
        if not isinstance(req, str):
            continue
        rn = _ensure_node(adir, "resource", req)
        if not _has_edge(adir, rn, fnode, "requires"):
            ag.add_edge(adir, rn, fnode, "requires", confidence=finding.confidence,
                        evidence=list(finding.evidence_refs), validation=val)
    for grant in list(getattr(finding, "grants", []) or []):
        if not isinstance(grant, str):
            continue
        gn = _ensure_node(adir, "resource", grant)
        if not _has_edge(adir, fnode, gn, "grants"):
            ag.add_edge(adir, fnode, gn, "grants", confidence=finding.confidence,
                        evidence=list(finding.evidence_refs), validation=val)
    return {"finding_node": fnode,
            "nodes_added": _count_nodes(adir) - nodes_before,
            "edges_added": len(ag.edges(adir)) - edges_before}


def _count_nodes(adir: Path) -> int:
    import sqlite3
    try:
        with sqlite3.connect(Path(adir) / "attack_graph.sqlite") as c:
            return c.execute("SELECT COUNT(*) FROM nodes").fetchone()[0]
    except sqlite3.Error:
        return 0
```

```python
def fix_ranking(assessment_dir, confirmed_paths) -> list[dict]:
    counts: dict[str, int] = {}
    for p in confirmed_paths:
        for node in set(p):
            counts[node] = counts.get(node, 0) + 1
    ranked = [{"node": n, "breaks": c} for n, c in counts.items()]
    ranked.sort(key=lambda r: (-r["breaks"], r["node"]))
    return ranked
```
