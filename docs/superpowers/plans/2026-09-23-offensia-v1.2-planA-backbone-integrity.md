# OffensIA v1.2 — Plan A: Backbone Integrity (remaining melhoria.md items)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining code-accurate integrity gaps from `melhoria.md`: make MCP-driven assessments visible/resumable, validate capability↔tool binding, formalize a per-tool effects policy, remove the last legacy command-string execution path, make an experiment an atomic transaction (single lock across all legs), fix the two oracles that can mis-verdict, add a real health-aware halt, and make the budget reflect real traffic.

**Architecture:** All active execution already flows `typed job → validate → serial executor (lock/actions/checkpoint) → capability registry → adapter → normalizer → oracle/evidence/ledger`. This plan hardens that spine: the executor gains a caller-held lock so `offensia_run_experiment` runs baseline/candidate/negative under ONE lock (no interleaving); `validate_job` gains capability-binding, single-target and effects checks; `offensia_validate_finding` loses its `run_command` checks-list branch (validation is oracle-driven only); the OAST oracle distinguishes "window still open" from "disproven"; the HTTP-differential oracle compares normalized features (via `digest`) instead of raw bodies; a real health probe (adapter `/health` + status/latency deltas) can halt a degrading target; and the engine reports a real `probe_count` the budget charges against.

**Tech Stack:** Python 3.11+, stdlib only, `mcp` (pinned `>=1.2,<2`), pytest/ruff/mypy, reference engine (stdlib HTTP) for dev/self-test.

**Spec:** `docs/specs/2026-09-23-offensia-v1.2-autonomous-core.md` + accepted `melhoria.md` §3.3, §3.4, §3.5, §3.6, §3.7, §3.8, §4.1, plus the Plan 2.5-B final-review item 0 (MCP assessment visibility).

## Global Constraints

- Python 3.11+; stdlib only; no new dependency; `mcp` pin unchanged.
- No `shell=True`, no `" ".join(argv)` on any active exec path.
- Non-disruptive invariant: a job that declares (or is classed) availability impact is refused; a hit cap terminates the job (no loop-retry).
- Non-destruction invariant: a job that declares deletion/mutation of pre-existing target objects is refused; only self-created (`origin=offensia` / `creates_test_object`) writes are allowed.
- Evidence-first: a finding is confirmed only by an oracle verdict; no exit code / HTTP 200 / timeout / block page / reflection confirms.
- Adapters/oracles never raise into the MCP layer except `CapExceeded` (executor maps it to a terminal state).
- Backward compatible: existing `state.json` / `findings.json` / assessments still load.
- Each task is TDD, runs with no live external target (mocked engines/providers, fabricated oracle inputs, injected clock), and leaves `ruff check .`, `mypy offensia`, `pytest -q` green before its commit. Baseline: branch from current `main` HEAD (137 passing).

## Review Focus

- **Held-lock leak / deadlock:** if a caller passes a lock to `run_job`, `run_job` must NOT release it; if it acquires its own, it MUST release it on every path (success, refusal, exception). (Task 5)
- **Experiment interleaving:** while an experiment holds the lock, a concurrent `offensia_run_job` must get `BUSY`, not run between legs. (Task 5)
- **Capability spoofing:** a job whose `capability` disagrees with `TOOL_SPECS[tool_id].capability` is refused (prevents wrong-adapter routing). (Task 2)
- **Method/effect mismatch:** a `generic_http` job using `-X DELETE/PUT/PATCH/POST` while its tool declares no mutation is refused. (Task 3)
- **OAST premature verdict:** no callback with the window still open is `inconclusive`, not `disproven`; only a closed window with no callback is `disproven`. (Task 6)
- **HTTP-diff dynamic-content false positive:** a baseline vs candidate that differ only in a CSRF token / timestamp / nonce must NOT be `confirmed`. (Task 7)
- **Validation without a live tool:** removing the `run_command` checks-list path must not leave any finding promotable without an oracle verdict. (Task 4)

**Files:**
- Modify: `offensia/core/executor.py`

- Test: `tests/test_experiment_atomic.py`

**Interfaces:**
- Consumes: `acquire_lock`, `Lock`, `LockHeld`, `run_job`.
- Produces:
  - `run_job(adir, job, *, scope_file, runner, health_probe=None, now=time.monotonic, lock=None)`: when `lock is None`, acquire its own lock (returning `BUSY` on `LockHeld`) and release it in `finally`; when a `lock` is passed, use it and DO NOT acquire or release (the caller owns it).

```python
"""Health-aware halt: detect target degradation so an effect can't be misattributed."""
from __future__ import annotations

from collections.abc import Callable

LATENCY_FACTOR = 5.0
LATENCY_FLOOR_MS = 25.0


def degraded(baseline: dict, sample: dict) -> bool:
    if baseline.get("ok") and not sample.get("ok"):
        return True
    b, s = baseline.get("latency_ms"), sample.get("latency_ms")
    if b and s and b >= LATENCY_FLOOR_MS and s > b * LATENCY_FACTOR:
        return True
    return False


def make_probe(check: Callable[[], dict], *, on_degrade: Callable[[dict, dict], None] | None = None):
    state: dict = {"baseline": None}

    def probe(target: str) -> bool:
        sample = check()
        if state["baseline"] is None:
            state["baseline"] = sample
            return bool(sample.get("ok", True))
        if degraded(state["baseline"], sample):
            if on_degrade:
                on_degrade(state["baseline"], sample)
            return False
        return True

    return probe
```
